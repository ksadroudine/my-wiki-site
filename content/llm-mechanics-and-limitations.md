## Summary

How large language models actually generate text — token-by-token prediction, parameters, context windows, temperature, and stopping conditions. Covers the four categories of limitation that follow directly from this mechanism — reasoning, knowledge, understanding, planning — none of which can be fully eliminated by better prompting alone. A McKinsey explainer adds the business-oriented view of what generative AI is and its mitigation options.

## Highlights

- An LLM generates output one token (word or sub-word unit) at a time, in a loop where an external software system feeds each new token back into the input and asks for the next one, until a stopping condition (an "end of sequence" token learned during training, a maximum-length limit, or a user-defined stop sequence) is triggered — the decision to stop is an interaction between the model's own predictions and external control logic, not a decision the model makes alone. <span class="src">How LLMs Work — Top 10 Executive-Level Questions</span>

- Model behavior hinges on three factors: parameters (the trainable weights encapsulating relationships learned from training data — GPT-3 has 175 billion of them, and more parameters generally means more nuanced knowledge), training data volume measured in tokens (GPT-3 trained on roughly half a trillion tokens; larger, more diverse data improves generalization), and context window size (how much prompt text the model can consider at once — GPT-3's was 2,000 tokens — with a larger, more detailed context generally improving prediction accuracy). <span class="src">The Working Limitations of Large Language Models</span>
- Retrieval-augmented generation (RAG) remains useful even with today's million-token context windows, for three reasons: overloading the context with irrelevant material can hurt output quality; models don't attend equally well to all parts of a long prompt, tending to focus more on the beginning and end and missing information buried in the middle; and longer prompts cost more and respond more slowly, which matters in real-world production use. <span class="src">How LLMs Work — Top 10 Executive-Level Questions</span>
- Hallucination cannot be fully eliminated with current LLM technology, because it arises from the model's fundamentally probabilistic token-prediction mechanism rather than from any process of verifying facts against a reliable source — prompt engineering, RAG, domain-specific fine-tuning, and rule-based post-processing checks can reduce hallucination for specific use cases but cannot guarantee its absence, including in cited sources, which LLMs can fabricate or misattribute just as readily as any other content. <span class="src">How LLMs Work — Top 10 Executive-Level Questions</span>

## Concept

At the mechanical level, an LLM does one thing repeatedly: predict the single most likely next token (a word or sub-word unit) given everything that came before it, append that token to the running text, and repeat. An external software system — not the model itself — runs this "generate the next token; append it; generate the next token" loop and decides when to stop, based on a combination of the model's own predictions (it learns during training to predict a special "end of sequence" token where a training example's answer was complete) and external rules like a maximum token limit or a user-defined stop sequence. This matters practically because it means the appearance of a model "deciding" it's done answering is actually an interaction between the model's statistical predictions and separately configurable software logic, which is exactly the kind of parameter a team building an LLM application can and should tune deliberately rather than treating as a fixed property of the model. <span class="src">How LLMs Work — Top 10 Executive-Level Questions</span>

Three technical factors shape what a given model can do: parameters, the trainable numerical weights that encode relationships the model extracted from its training data (more parameters generally correlating with more nuanced, more knowledgeable output); training data volume, measured in tokens, where a larger and more diverse training corpus generally improves the model's ability to generalize to situations it wasn't directly trained on; and context window size, the amount of prompt text the model can take into account at once, where a larger, more detailed context generally improves prediction accuracy for the immediate task. A related, frequently misunderstood point is that a model does not learn from a single correction in real time — if a user tells ChatGPT it made a mistake, that correction might inform a future training run weeks or months later if it's included in that run's data, but the running model itself does not update. What looks like "memory" of an earlier conversation is typically a separate feature that stores specific facts (a user's name, stated preferences, recurring topics) and silently re-injects relevant stored facts into a new conversation's prompt behind the scenes — the model is being fed reminders as input, not genuinely recalling a past interaction. This same mechanism explains why retrieval-augmented generation (RAG) remains valuable even as context windows have grown to the million-token range: overloading a prompt with excess or irrelevant material measurably degrades output quality; models don't weigh all parts of a long prompt equally, tending to attend more to the beginning and end and missing details buried in the middle; and longer prompts cost more and run slower in production, all of which argue for deliberately retrieving and including only the most relevant material rather than simply stuffing everything into an expanded context window. <span class="src">How LLMs Work — Top 10 Executive-Level Questions</span>

Hallucination — confident, plausible-sounding output that is nonetheless fabricated or wrong — is a structural consequence of this token-prediction mechanism rather than a bug that better engineering will eventually eliminate: because the model generates text by predicting statistically likely token sequences rather than verifying claims against any ground-truth source, some risk of hallucination is inherent to how the technology works. Prompt engineering, RAG, domain-specific fine-tuning, and rule-based post-processing checks can each reduce hallucination rates for a given use case, but none can guarantee its absence — and this extends to citations the model provides in support of its own answers, which can be just as readily fabricated or misapplied as any other generated content, meaning a citation should never be trusted without independent verification that the source actually exists and genuinely supports the claim attributed to it. <span class="src">How LLMs Work — Top 10 Executive-Level Questions</span>

Beyond hallucination specifically, LLMs exhibit four broader categories of practical limitation that follow from the same underlying mechanism. Reasoning limitations mean LLMs verbally simulate individual logical rules convincingly but do not reliably chain them together into valid multi-step conclusions — demonstrated by a cabbage-classification logic puzzle where a model confidently gives the wrong answer — compounded by the fact that each step in a multi-step argument carries its own nonzero probability of error, and the model often cannot explain the actual chain of reasoning that produced its answer, making errors hard for a human reviewer to catch after the fact. Knowledge and expertise limitations mean the model's knowledge is bounded by (and can reproduce errors present in) its training data, producing both outright fabrication (invented academic citations, invented case law) and genuine inconsistency, where the same underlying question can receive materially different answers depending on subtle differences in phrasing or on when it's asked. Understanding limitations mean the model can simply misread the actual logical structure of a prompt — demonstrated by a nested-boxes puzzle the model gets backwards — which is especially damaging in practice because it's hardest to catch precisely when the user asking the question doesn't know the domain well enough to notice the model missed the point, or to write a better prompt in the first place. Planning and execution limitations mean step-by-step-looking plans the model produces can be practically naive, since the model doesn't independently question whether a stated goal is realistic or interrogate the accuracy of the user's own stated assumptions the way a competent human advisor would. The real-world stakes of these limitations were demonstrated in a field experiment with more than 750 Boston Consulting Group consultants: participants using GPT-4 on a specific business reasoning task got the answer wrong 23 percent more often than a no-AI control group, not primarily because the model was wrong more often in isolation, but because its confidently-argued, persuasive rationale led users to accept a wrong answer at face value rather than independently verifying it. <span class="src">The Working Limitations of Large Language Models</span>

Given that none of these limitations can be engineered away entirely, the practical response is to design LLM applications around them rather than assume they'll disappear with the next model release. Keeping a human in the loop for validation remains the most reliable safeguard for open-ended tasks, with sampling or risk-based triage used to manage the cost of human review at scale rather than reviewing every output. For structured or high-volume tasks, a second "AI judge" — typically another LLM tasked with evaluating the first model's output — offers a scalable alternative, with the important caveat that the judge model can itself hallucinate or fail to match human judgment, particularly on complex cases, which argues for combining judge feedback with retrieval-based fact-checking or escalating low-confidence outputs to a human. Beyond process design, complementary technologies can directly address specific limitation categories: knowledge graphs and dedicated reasoning engines to strengthen multi-step logical inference, and domain-specific fine-tuned models (trained on specialized data, such as medical-licensing-exam-caliber models trained on clinical literature) to strengthen expertise in a narrow field beyond what a general-purpose model's broad training data can support. <span class="src">The Working Limitations of Large Language Models</span>
