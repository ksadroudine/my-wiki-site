## Summary

This glossary defines the terms that appear most often in the Cloud part of the Book of Knowledge. Each entry gives a short plain-language definition and points to the Concept where the term is explained in depth. Terms are listed in alphabetical order.

## Glossary of Cloud Terms

| Term | Meaning | See |
|------|---------|-----|
| Availability (the nines) | The share of time a service is working. A target of 99 percent allows about 3.65 days of downtime a year, and 99.999 percent allows about five minutes. | [Cloud Operations, Data and Security](#/concept/cloud-operations-data-and-security) |
| Capital expenditure (CapEx) | Spending on owned or leased assets such as servers and licenses, which is recorded over several years. | [Cloud Strategy and Migration](#/concept/cloud-strategy-and-migration) |
| Cloud-native | Built as small, independently deployed services packaged in containers and managed dynamically. The term describes how an application is built, not where it runs. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Consumption Gap | The distance between the value a product could deliver and the value customers realize from it. | [Cloud and SaaS Business Economics](#/concept/cloud-and-saas-business-economics) |
| Container | A package that holds application code with everything it needs, so that it runs the same way in different environments. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Data sovereignty | The principle that stored data is subject to the laws of the country where it physically sits. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| DevOps | A way of working that merges development and operations so that features ship as soon as they are ready. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| FinOps | The practice of managing and optimizing cloud spending. | [Cloud Operating Model Design](#/concept/cloud-operating-model-design) |
| Hybrid cloud | Private and public cloud resources that work together toward a shared goal. Separate environments that merely coexist do not count. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Infrastructure as a service (IaaS) | A virtual server, including its operating system, supplied as a service. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Kubernetes | The dominant open-source system for managing large numbers of containers, which runs on any public cloud, private cloud or company-owned hardware. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Lift and shift (rehost) | Moving an application to the cloud as it is, without changing its design. | [Cloud Strategy and Migration](#/concept/cloud-strategy-and-migration) |
| Microservice | A small program that does one narrow job and talks to other services only through standard interfaces. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Monolith | A single large application with many internal dependencies, which is hard to change or to scale in parts. | [Cloud Strategy and Migration](#/concept/cloud-strategy-and-migration) |
| Multicloud | The coordinated use of two or more public clouds. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Multi-tenancy | A design in which many customers share the same infrastructure and software while their data stays separate. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Operating expense (OpEx) | The ongoing cost of running the business, which covers most cloud services. | [Cloud Strategy and Migration](#/concept/cloud-strategy-and-migration) |
| Platform as a service (PaaS) | Middleware, development tools and deployment services that hide the operating system from developers. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Private cloud | A cloud owned and operated by or exclusively for one organization, usually behind its firewall. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Public cloud | A cloud owned and operated by a third party for use by many customers. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Rightsizing | Matching the capacity of a workload to what it needs before or after moving it. | [Cloud Strategy and Migration](#/concept/cloud-strategy-and-migration) |
| Rule of 40 | A test for software companies. Growth rate plus profit margin should exceed 40 percent. | [Cloud and SaaS Business Economics](#/concept/cloud-and-saas-business-economics) |
| Service level agreement (SLA) | A contract that states the level of service a provider promises, such as uptime. | [Cloud Operations, Data and Security](#/concept/cloud-operations-data-and-security) |
| Shadow IT | Technology that employees or departments adopt without the knowledge of the IT organization. | [Cloud Operations, Data and Security](#/concept/cloud-operations-data-and-security) |
| Shared-responsibility model | The division of security duties in which the provider secures part of the environment and the customer secures the rest. | [Cloud Operations, Data and Security](#/concept/cloud-operations-data-and-security) |
| Software as a service (SaaS) | A complete multi-tenant business application delivered over the internet. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Virtualization | Separating software from the hardware it runs on, so that one physical machine can host many virtual ones. | [Cloud Computing Foundations](#/concept/cloud-computing-foundations) |
| Zero Trust | A security model in which no user or device is trusted by default. | [Cloud Operating Model Design](#/concept/cloud-operating-model-design) |
