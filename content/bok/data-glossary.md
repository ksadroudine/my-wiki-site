## Summary

This glossary defines the terms that appear most often in the Data part of the Book of Knowledge. Each entry gives a short plain-language definition and points to the Concept where the term is explained in depth. Terms are listed in alphabetical order.

## Glossary of Data Terms

| Term | Meaning | See |
|------|---------|-----|
| Big data | Data so large, varied and fast-changing that conventional data management cannot cope. It is described by three features, which are volume, variety and velocity. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Classification | A learning task that predicts a known category, such as fraud or not fraud, from labeled examples. | [Data Mining Fundamentals](#/concept/data-mining-fundamentals) |
| Clustering | A learning task that groups similar examples together without predefined labels. | [Data Mining Fundamentals](#/concept/data-mining-fundamentals) |
| CRISP-DM | A standard six-phase process for data mining projects, from business understanding to deployment. | [Data Mining Fundamentals](#/concept/data-mining-fundamentals) |
| Data accountability | Responsibility for the quality, security and appropriate use of a dataset, which is kept separate from ownership of the data. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Data balance sheet | An internal record of the value of a company's data assets, kept without settling the formal accounting treatment. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Data contract | An agreement between the creators and users of data that sets the quality standards the data must meet. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Data mesh | An architecture in which the teams that create data are responsible for its quality. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Data monetization | Turning proprietary data into revenue, directly or by building it into other offerings. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Data product manager | A person who translates business needs into data products that people adopt, and who coordinates the teams involved. | [Data Leadership Roles Evolution](#/concept/data-leadership-roles-evolution) |
| Data steward | A person accountable for a data domain across its life cycle and across business processes. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| ELT | A pipeline design in which raw data is loaded first and transformed only when an analysis needs it. The older design, ETL, transforms data before loading. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Federated learning | A way to train a shared AI model across several organizations by sending the algorithm to each one's data, so that no raw data is handed over. | [Federated Machine Learning](#/concept/federated-machine-learning) |
| First-party data | Data that a company gathers directly from its own customers. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Holdout set | A portion of data kept aside from training to test a model. It resembles the training data and is no substitute for testing on future data. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Knowledge graph | A store of entities and the relationships between them that lets AI agents reason across business data. | [Semantic Layer for Agentic AI](#/concept/semantic-layer-for-agentic-ai) |
| Model drift | The decline in a model's accuracy as the data or the world changes after deployment. | [Data Leadership Roles Evolution](#/concept/data-leadership-roles-evolution) |
| Ontology | A formal description of how business entities, such as customers and products, relate to one another. | [Semantic Layer for Agentic AI](#/concept/semantic-layer-for-agentic-ai) |
| Overfitting | A fault in which a model fits its training data more closely than it fits new data. | [Data Mining Fundamentals](#/concept/data-mining-fundamentals) |
| Right data | A concept and not a dataset. It is the data that fits the problem and population and meets six criteria, including relevance, freedom from bias and timeliness. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
| Semantic debt | The accumulated problem of the same business term having different definitions in different systems. | [Semantic Layer for Agentic AI](#/concept/semantic-layer-for-agentic-ai) |
| Semantic layer | A machine-readable layer of shared definitions, relationships and rules that lets AI agents interpret enterprise data consistently. | [Semantic Layer for Agentic AI](#/concept/semantic-layer-for-agentic-ai) |
| Wrangling | The work of preparing data for analysis, which commonly takes 50 to 80 percent of an analyst's time. | [Enterprise Data Strategy and Governance](#/concept/enterprise-data-strategy-and-governance) |
